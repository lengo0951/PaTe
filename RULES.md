# PasteFlow System Rules & Engineering Directives

**Repository:** `https://github.com/lengo0951/PasteFlow`  
**Author:** Quốc Ngô (`@lengo0951` / `coolstar17`)  
**Core Stack:** Native Swift 6 (macOS) & Native Rust 2024 (Windows)

---

## 1. 🌐 Dual-Platform Parity Directive (Bắt buộc cập nhật đồng thời macOS & Windows)

- **Zero Platform Discrepancy**:
  Whenever any feature, bugfix, UI component, shortcut, config option, or data model change is introduced, it **MUST be implemented, verified, and packaged for BOTH macOS and Windows**. Never leave one platform behind.
  * **macOS Implementation**: Pure native Swift 6, SwiftUI, and AppKit.
  * **Windows Implementation**: Pure native Rust 2024, Win32 APIs via `windows-rs` 0.58 (DWM Acrylic/Mica HUD).

- **Data & Schema Synchronization**:
  * Local storage files (`history.json`, `pinboards.json`, `config.json`) must remain strictly compatible across macOS (`~/Library/Application Support/PasteFlow/`) and Windows (`%APPDATA%\PasteFlow\`).
  * Any new attribute added to `ClipboardItem` (e.g., `customTitle`, `pinboardIDs`, `checksum`, `appName`) must be simultaneously added to:
    - Swift: `Sources/Models/ClipboardItem.swift`
    - Rust: `windows/src/core/types.rs`
  * Features like custom clip renaming, quick look preview, pinboards, filter pills, and hotkey rebinding must exist symmetrically on both platforms.

- **Dual-Release Packaging Mandate**:
  Every release cycle (`vX.Y.Z`) MUST build, test, calculate SHA-256 checksums, and publish BOTH artifacts:
  1. `build/PasteFlow-<version>.dmg` (macOS Apple Disk Image with `/Applications` symlink via `./package_dmg.sh`).
  2. `build/PasteFlow-v<version>-windows.zip` (Windows package containing `pasteflow.exe` PE32+ GUI binary, `install.bat`, `uninstall.bat`, `README.txt` via `./package_windows.sh`).

## 2. ⚡ Performance-First & Zero-Bloat Mandate (Tối ưu hiệu năng là ưu tiên số 1)

Performance and resource efficiency are the foundational principles of PasteFlow. Any feature that noticeably degrades memory, CPU, or responsiveness will be rejected.

- **Strict Memory Footprint Caps (Resident Set Size - RSS)**:
  * **macOS Target**: `< 35 MB RSS` idle (~30 MB typical).
  * **Windows Target**: `< 25 MB RSS` idle (~20 MB typical).
  * **Zero Memory Leak / Bitmap Traps**:
    - Never hold raw, uncompressed full-resolution bitmaps (e.g., TIFF, raw RGBA) in resident memory.
    - Application icons must be strictly downscaled to 32×32 with an LRU cache (`AppIconCache`).
    - Clipboard images must be written directly to disk (`~/.../images/`) and loaded on-demand via a bounded `NSCache` (limit: 30 images).

- **Idle CPU Consumption (< 0.1%)**:
  * The background daemon MUST consume near **0.0% CPU** when idle.
  * On macOS: Clipboard change detection uses lightweight changeCount checks and checksum comparisons throttled at 500ms intervals.
  * On Windows: Uses native event-driven Win32 `AddClipboardFormatListener` and `WM_CLIPBOARDUPDATE` messages — zero active polling loops.

- **Absolute Ban on Heavy Frameworks & Webviews**:
  * **STRICTLY PROHIBITED**: Electron, Chromium, WebView2, CEF, Node.js, Python, or any webview container for the core application or UI.
  * PasteFlow is and must forever remain **100% native compiled code** with microscopic distribution sizes (~2 MB DMG, ~200 KB Windows Zip).

- **Sub-50ms Interaction Latency**:
  * Summoning the HUD via global hotkey (`⌘ ⇧ V` / `Ctrl + Shift + V`) must display in **< 50 milliseconds**.
  * Auto-paste simulation via `CGEvent` (macOS) and `SendInput` (Windows) must execute instantaneously.
  * Card rendering must utilize double-buffered GDI / native AppKit render loops to guarantee buttery 60/120fps scrolling across 500+ items.

---

## 3. 🛡️ Privacy & Sensitive Data Safety

- Password managers (`1Password`, `Bitwarden`, `KeePassXC`, `Keychain Access`) are blacklisted by default and must never have their contents captured or written to disk.
- Self-paste loops must be prevented using `org.nspasteboard.AutoGeneratedType` (macOS) and registered clipboard formats (Windows).
- All clipboard history remains 100% local on the user's machine; zero telemetry, zero analytics, zero external network requests.
